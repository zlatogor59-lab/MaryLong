# Сервер приложения консультанта

Первый безопасный каркас по спецификации Obsidian. Реальные клиентские данные не используются.

## Локальный запуск

1. Скопировать `.env.example` в `.env` и заменить демонстрационные значения.
2. Запустить PostgreSQL 16+.
3. Выполнить `pnpm install`, `pnpm prisma:generate`, `pnpm prisma:migrate`.
4. Запустить `pnpm start:dev`.

После запуска web-интерфейс доступен на `http://localhost:3000/`. Вход использует OIDC Authorization Code + PKCE. Укажите `AUTH_CLIENT_ID` и redirect URI в `.env`; client secret для SPA не используется. Access token хранится только в памяти страницы.

При установленном Docker локальный PostgreSQL запускается командой `docker compose up -d postgres`. Конфигурация привязывает порт только к `127.0.0.1` и предназначена исключительно для синтетических данных.

Публичная проверка: `GET /api/v1/health`. Остальные маршруты закрыты глобальным guard.

## Границы текущего шага

- Созданы первые шесть таблиц и ограничения базы.
- Создана проверка OIDC JWT и прикладного отзыва сессии.
- `users` подключён через Prisma; `/me` возвращает только безопасный DTO.
- Политики AUTH-005–010 реализованы и покрыты тестами.
- Для фактической проверки миграции требуется PostgreSQL 16+; в текущей среде Docker/PostgreSQL отсутствуют.
- Реализован `POST /api/v1/clients/{client_id}/submissions/import-preview`: точное позиционное распознавание v1/v2, согласие, дубли, идемпотентность, шифрование и payload hash.
- Реализован multipart `POST /api/v1/clients/{client_id}/submissions/import-preview/csv` с лимитом 2 МБ и одной анкетой на запрос.
- Accept/reject и аудит выполняются одной транзакцией PostgreSQL.
- Локальный rate limiter допускает 10 попыток импорта на пользователя/клиента в минуту; перед несколькими экземплярами API его нужно заменить распределённым хранилищем.
- Шифрование чувствительных полей выполняется приложением/KMS; открытый текст в базе не хранится.
- `GET /api/v1/clients` показывает консультанту только клиентов из его активных назначений.
- В `web/` добавлен первый интерфейс: выбор клиента, multipart-загрузка одного CSV, безопасный preview и действия accept/reject.
- Локальный UI smoke test использует только `test/fixtures/consultant-ui-synthetic.csv` и `test/consultant-ui-mock-server.mjs`.
- `GET /api/v1/auth/config` отдаёт только публичные настройки SPA; секретов в ответе нет.
- `GET /api/v1/clients/{client_id}/submissions` возвращает последние безопасные метаданные анкет только при активном назначении консультанта.
- Реальный локальный OIDC-вход проверен с Auth0 EU: сервер распознаёт связанного консультанта и возвращает только назначенного синтетического клиента.
